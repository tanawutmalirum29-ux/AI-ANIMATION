# AI Training Lab — ระยะเตรียมข้อมูล

สถานะ: **Data intake + measured evaluation + deterministic timing correction + CPU SGD demo** (ฝึกน้ำหนักทดลองจากข้อมูลสังเคราะห์ได้ แต่ยังไม่มีโมเดลที่ผ่านการฝึกจากข้อมูลมนุษย์อนุมัติและพร้อมใช้จริง)

## หลักการ
ผู้ใช้รับผิดชอบเลือก/อนุมัติเนื้อเรื่องจาก AI ภายนอก ผู้ช่วยใน Story Studio รับผิดชอบจังหวะภาพ เสียง การแบ่งตอน และ QA โดยไม่เปลี่ยนเนื้อเรื่องตามอำเภอใจ

## วิธีใช้งาน
1. คัดลอก [STORY_AUTHOR_PROMPT_TH.md](./STORY_AUTHOR_PROMPT_TH.md) ส่งให้ AI ภายนอก
2. นำ JSON ที่ได้รับมาตรวจ syntax และนำเข้า Story Studio
3. เก็บต้นฉบับที่อนุมัติไว้ใน `training-lab/datasets/approved/` (สร้างโฟลเดอร์เมื่อมีข้อมูลจริง)
4. เก็บกรณีทดสอบแยกจากผลงานจริงใน `training-lab/datasets/fixtures/`
5. บันทึกผลตรวจที่อิงหลักฐาน เช่น ความยาวเสียงจริง จุดตัดฉาก และข้อผิดพลาด ไม่ใช้คะแนนที่ AI แต่งเอง
6. แบ่งชุดข้อมูลตาม **เรื่อง** เป็น train / validation / test ก่อนฝึก เพื่อป้องกันฉากจากเรื่องเดียวกันรั่วข้ามชุด

## สิ่งที่จะวัด
- ความถูกต้องของ JSON และการอ้างอิง ID
- เสียงพากย์ครบ ไม่มีการตัดหรือทิ้งเนื้อหา
- สัดส่วนตอนที่มีความยาว 60–65 วินาทีเมื่อแบ่งได้อย่างปลอดภัย
- เวลาภาพค้างหลังเสียงจบ และความคลาดเคลื่อนของซับ
- ความต่อเนื่องของตัวละคร/ตำแหน่ง/เหตุการณ์ (ต้องมี QA เชิงภาพเพิ่มเติม)
- จำนวนครั้งที่ผู้ใช้ต้องแก้เอง เทียบ baseline

## ข้อจำกัด
ข้อมูลสังเคราะห์ไม่ยืนยันความสามารถในงานจริง โมเดลขนาดเล็กไม่สามารถเข้าใจเนื้อเรื่องเชิงลึกโดยอัตโนมัติ การเพิ่มความสามารถต้องผ่านการทดสอบกับข้อมูลที่ไม่ใช้ฝึกและได้รับการอนุมัติ การติดตั้งโมเดลต้องมี rollback และไม่กระทบ production ระหว่างทดลอง

## กรณีประเมินจริง: สามแสงก่อนรุ่งสาง (2026-11-01)

- [รายละเอียดตรวจผลงานภาพ/เสียง](./reviews/three-flashes-before-dawn-export-review.md)
- [หลักฐานเวลาเงียบที่วัดจาก MP4 ทั้ง 3 ตอน](./evaluations/three-flashes-export-audit.json)
- ตอนละ 6 ฉาก มีช่วงเสียงเบาต่อเนื่องหลังเสียงพูด/ก่อนการเปลี่ยนฉาก 2.45–2.71 วินาที รวม 18 ช่วง
- ปรับ `studio-timing-auditor.js` ให้เสนอตัดช่วงเงียบท้ายฉากเมื่อไม่มีเหตุการณ์ที่ต้องรักษา และใช้ `planAutoDubTightening` ป้องกันตัดเสียงที่สร้างไม่ครบ/เสียงอัดมือ
- ใน Studio ให้เปิด **Sound Desk → พากย์อัตโนมัติ → เปิดผู้ช่วยจัดจังหวะ** หรือกด **จัดเฟรมคลิปพากย์เดิม** บนโปรเจกต์ที่มีคลิปเสียงจริงแล้ว; คำสั่งนี้ย้อนกลับได้
- ไฟล์ JSON ต้นฉบับที่ไม่มี `audioClips` ต้องสร้างเสียงก่อน; ไม่มีเสียงให้วัดก็ไม่มีการกระชับฉากอัตโนมัติ
- หลังปรับเวลา วิดีโออาจสั้นกว่า 60 วินาที; ระบบจะไม่เติมบท/ภาพนิ่ง/ความเงียบเพื่อให้ครบเป้า

ทดสอบเฉพาะกฎจากตัวอย่างจริง: `node tests/three-flashes-pacing-regression.test.cjs`

**หมายเหตุ:** นี่คือการปรับกฎผู้กำกับเสียงด้วยข้อมูลวัดจริงและ Regression QA ไม่ใช่ Fine-tuning/LoRA การฝึกโมเดลจำเป็นต้องมีข้อมูลได้รับอนุมัติมากกว่าเรื่องเดียว พร้อมชุดทดสอบคนละเรื่องและทรัพยากรฝึกจริง

## ผลงานใหม่ล่าสุด — เปรียบเทียบการส่งออกก่อน/หลัง (2026-11-01)

- [ไฟล์ตัวเลขเทียบวิดีโอ 3 ตอนและความเสี่ยงภาพ](./evaluations/three-flashes-v2-comparison.json)
- ความยาววิดีโอใหม่ **38.105 / 37.383 / 36.942 วินาที** จากเดิม **47.105 / 46.383 / 45.933 วินาที** ลดเวลาประมาณ 9 วินาที/ตอน
- ช่วงเสียงเบารอยต่อฉาก (เกณฑ์ -35 dB) ลดจากเฉลี่ย ~2.6 วินาทีเหลือ ~1.1 วินาที วิดีโอใหม่ทั้งสามมีแทร็ก AAC ไม่ได้หายไป
- การปรับเวลาอย่างเดียว **ยังไม่แก้ภาพตามเรื่อง**: สะพานถล่ม กล่องเครื่องมือตก (s08), เครื่องกล/สายพาน (s11–s12), แสงสามวาบ (s15) ยังไม่เห็นชัดในเฟรมที่สุ่มตรวจ ส่วน s07/s10 เสี่ยงตัวละครซ้อนทับ
- เพิ่ม `studio-visual-qa.js` เพื่อให้ AI-1 ตรวจการสั่งเหตุการณ์ด้วยข้อความที่ยังไม่มีพร็อพหรือคีย์เฟรมจริง และเตือนตำแหน่งตัวละครใกล้กัน (ตรวจ JSON เชิงสถิตเท่านั้น ยังไม่ใช่ระบบเข้าใจวิดีโอ)
- **ห้าม** เพิ่มวัตถุ ภาพ เอฟเฟกต์หรือแก้ JSON อัตโนมัติจากคีย์เวิร์ดโดยไม่รู้ความหมายของฉาก; ผู้เขียนภายนอกต้องจัดทำข้อมูลภาพที่ระบบรองรับ จากนั้นตรวจผลวิดีโอจริง
- **แยกข้อมูล**: JSON ต้นฉบับใช้อ้างอิงความตั้งใจ ผู้ผลิตใช้คลิปส่งออกวัดผล ก่อนเก็บเป็นชุดข้อมูลฝึกต้องอนุมัติตัวอย่างที่แก้ถูกต้องแล้วเท่านั้น

ชุดข้อมูลนี้เป็น **evaluation only**; ไม่ใช่ตัวอย่างที่รับรองว่าแก้แล้วถูก และไม่ได้ฝึกโมเดลน้ำหนักจริง

### แก้บรรยากาศฝนในฉากภายในอาคาร

- ภาพที่สุ่มตรวจแสดงฝนโปรยเต็มเฟรมแม้อยู่ในห้องซ่อม (`workshop`) และห้องโคมไฟ (`tower`)
- Preview และ Export ใช้ `sceneWeatherType` ร่วมกัน: กรองฝน/พายุ/หิมะที่ตกกลางห้องภายในอาคารโดยตรวจ `locations[].name/promptBlock`
- ฉากกลางแจ้งยังแสดงบรรยากาศปกติ และผู้เขียนระบุ `scenes[].weatherExposure: "outdoor"` ได้เมื่อฉากนั้นเปิดรับฝนจริง; `"indoor"` ใช้ปิด
- ไม่ได้เพิ่มภาพหน้าต่าง/ฝนหลังหน้าต่างในฉากเดิม และยังต้องตรวจผลลัพธ์จริงหลัง Deploy

## รอบประเมินที่ 3 — แม่แบบ SVG รุ่นแรกทำให้ฉากเงียบยาว (2026-11-01)

หลักฐาน: [three-flashes-v3-factory-export.json](./evaluations/three-flashes-v3-factory-export.json)

ตรวจไฟล์ MP4 ชุดใหม่ทั้งสามตอนด้วย ffprobe, ffmpeg silencedetect เกณฑ์ -35 dB (ช่วงอย่างน้อย 0.35 วินาที), และสุ่มดูภาพ 20 เฟรมต่อหนึ่งตอน:

- ตอน 1 = 38.105 วินาที **ไม่เปลี่ยน**; ช่องเสียงเบาแต่ละรอยต่อยังประมาณ 1.1 วินาที
- ตอน 2 = **49.267 วินาที** จาก 37.383 วินาที (เพิ่ม 11.883 วินาที); พบเสียงเบาต่อเนื่องกว่า 4 วินาที **3 ช่วง**
- ตอน 3 = **52.983 วินาที** จาก 36.942 วินาที (เพิ่ม 16.042 วินาที); พบเสียงเบาต่อเนื่องกว่า 4 วินาที **4 ช่วง**
- ทั้งสามมี AAC audio stream จริง จึงไม่ใช่กรณีไม่มีแทร็กเสียง; ยังไม่ได้ถอดคำพากย์เพื่อตรวจความครบทุกคำ
- ในตอน 2–3 สะพาน/กล่องเครื่องมือ/แผ่นสะท้อน/แสงกะพริบเริ่มวาดได้ แต่แม่แบบยังใหญ่เกินเฟรมแนวตั้งในบางฉาก ตัวละครอาจซ้อนกัน และเลเยอร์น้ำท่วมบังฉาก ข้อสังเกตจากเฟรมที่สุ่ม ไม่ใช่การรับรองวิดีโอทั้งเรื่อง

**สาเหตุเชิงโค้ดที่พบ:** เดิม Timing Auditor มอง `customAssets[].motionKeys` จากระบบสร้าง SVG ของตัวเองว่าเป็น Keyframe เรื่องที่ห้ามแก้เวลา จึงรักษาเวลาฉากเก่าเต็ม 10 วินาทีแม้จบเสียงพากย์แล้ว

**สิ่งที่ปรับเป็นกฎทดสอบได้:**

1. อนุญาตบีบจังหวะเฉพาะวัตถุที่ระบุ `producer: "studio-production-v1"` และไม่ได้ล็อกด้วย `productionManualLock`, ลดเวลาฉากตามเสียงพากย์พร้อมย่อ Keyframe ของวัตถุทุกจังหวะไปด้วย
2. กฎเดียวกันสำหรับท่าเดินที่ผลิตโดยระบบ (มี `motionProducer`); ไม่แก้ Keyframe ที่ผู้เขียนกำหนดเอง, SFX ภายหลังเสียง, วิดีโอ, หรือ `[HOLD]`/`[PAUSE]`
3. ลดขนาด SVG **เฉพาะสินทรัพย์ร่างจากระบบ** เมื่อใช้จอ 9:16; ไม่เปลี่ยนขนาดสินทรัพย์ที่ผู้ใช้วางเอง
4. ปรับเอฟเฟกต์น้ำท่วมให้โปร่งและอยู่ต่ำลง; เพิ่ม QA ระยะห่างของตัวละครในเฟรมแนวตั้ง
5. เพิ่ม Regression Tests `tests/latest-export-feedback.test.cjs` และ `tests/production-pipeline.test.cjs` ควบคุมการคงอยู่ของทุก Keyframe ตลอด 6 ประเภทแม่แบบ รวมถึงยืนยันการรันซ้ำ

**สถานะ:** นี่คือ feedback/evaluation และการปรับโมดูลอัตโนมัติให้มีพฤติกรรมดีขึ้น **ยังไม่ได้ฝึกน้ำหนักโมเดล AI จริง** และยังไม่มี MP4 ที่เรนเดอร์หลังการแก้รอบนี้เพื่อตรวจรับผลลัพธ์จริง นำ JSON โปรเจกต์เดิมมาทดสอบการผลิตซ้ำ แล้วใช้ผลส่งออกจริงยืนยันอีกครั้งก่อนใช้เป็นตัวอย่างคำตอบที่ถูกต้อง

- [อ่านขั้นตอน CPU-first ML Lab, ขอบเขต ความเป็นส่วนตัว และเกณฑ์ QA](./CPU_LAYOUT_ML.md)
- เว็บไซต์เพิ่ม **ML Lab** เพื่อให้ผู้ใช้เลือกอนุมัติการจัดตำแหน่งตัวละครเป็นไฟล์ JSONL โดยตรง: ส่งออกเฉพาะตัวเลข ไม่ส่งไฟล์เสียง รูปภาพ หรือบท และไม่อัปโหลดข้อมูลอัตโนมัติ
- ตัวฝึก CPU ใช้ SGD อัปเดตน้ำหนักเชิงตัวเลขจริงบน GitHub Actions standard runner แต่ **โหมด demo ใช้ข้อมูลสังเคราะห์เท่านั้น**; ไม่ถือว่าโมเดลได้เรียนรู้จากผลงานจริงหรือใช้งานเชื่อถือได้
- ยังไม่มีข้อมูลอนุมัติจริงใน `datasets/approved/` จึงปฏิเสธการฝึกแบบ `approved` โดยตั้งใจจนกว่าจะมีตัวอย่างคนตรวจอย่างน้อย 60 แถวจากอย่างน้อย 5 เรื่อง
- โมเดลทุกตัวต้องผ่านการประเมินบนเรื่องที่ไม่อยู่ในข้อมูลฝึก เทียบกับ baseline และให้มนุษย์อนุมัติก่อนใช้งาน ไม่มี auto-deploy และยังไม่เปิด LoRA/QLoRA ในระบบผลิต
