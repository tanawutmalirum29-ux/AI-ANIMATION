# Shot ML — ฝึกน้ำหนักมุมกล้องจริงบน GitHub CPU (2026-11-02)

## สิ่งที่มีจริง

โมเดล `shot-framing` เป็น **ตัวจำแนกกล้องที่ดี/ควรจัดใหม่** สำหรับฉาก `coastal-harbor` panorama เท่านั้น ไม่ใช่ AI วาด SVG หรือโมเดลพากย์เสียง เป็น SGD logistic regression 10 คุณลักษณะ numeric (portrait, world, zoom, panDistance, targetOffset, gateOverlap, actorCount, moving, action, duration) ใช้ CPU GitHub Actions ไม่มี GPU ไม่มี external model API และไม่ใช้ CPU โทรศัพท์ฝึก

`training-lab/train-shot.py`: ปรับน้ำหนักจริงด้วย stochastic gradient descent; เปรียบเทียบ baseline กฎเดิมกับ macro-F1/accuracy ที่วัดจาก **เรื่องอื่น** ไม่ใช่เฟรมเดียวกัน

`studio-shot-ml.js`: โมเดลอนุมัติใช้พยากรณ์ว่ามุมที่เลือกเสี่ยงไม่ดีเท่าไร และเสนอมุมทางเลือก; ไม่สร้างบท ฉาก เสียง หรือเปลี่ยนโปรเจกต์จนผู้ใช้กดยืนยัน มุมที่ล็อก/มีภาพ/วิดีโอจะไม่ถูกแก้

## ลองดูการฝึกจริง (ใช้ข้อมูลสังเคราะห์ทดสอบระบบ)

1. ไปที่ [Actions — CPU Shot ML](https://github.com/tanawutmalirum29-ux/AI-ANIMATION/actions/workflows/cpu-shot-ml.yml)
2. งาน PR ในระบบ Shot ML จะฝึก **น้ำหนัก 10 ค่า** บน GitHub CPU ด้วย demo 432 แถว (12 กลุ่ม) และแสดงคะแนนใน Summary
3. ดาวน์โหลด artifact `cpu-shot-demo-pr`; โมเดลจะเป็น `status: demo-only, active: false` **ใช้กับงานผลิตไม่ได้** แม้น้ำหนักเรียนรู้จริง

## ให้ AI เรียนรู้จากผลงานที่คุณตรวจจริง

1. เปิดเว็บ AI-ANIMATION นำเข้าโปรเจกต์ของคุณ (เริ่มจากฉาก `coastal-harbor` ที่มีกล้อง panorama)
2. เปิด **AI Production → Shot ML**
3. ดูว่าภาพในพรีวิวตรงกับบทหรือไม่ แล้วกด **มุมกล้องดีแล้ว · เก็บตัวอย่าง** หรือ **มุมกล้องไม่ตรงบท · เก็บตัวอย่าง**
4. เก็บหลายฉากหลายเรื่องแล้วกด **ดาวน์โหลดตัวอย่าง** เพียงครั้งเดียว จะได้ไฟล์ `.jsonl` ซึ่งมีเฉพาะค่าตัวเลข คำตอบ และรหัสเรื่องแบบไม่ระบุตัวตน ไม่รวมบท ภาพ หรือเสียง โปรแกรมไม่ส่งข้อมูลออกเอง
5. ส่งไฟล์เหล่านั้นมาในแชตหรือให้ผู้ดูแลรวบรวมด้วย `python3 training-lab/prepare-shot-data.py --input *.jsonl --out shot-framing.jsonl`
6. ต้องมีอย่างน้อย **100 ตัวอย่างจาก 5 เรื่องขึ้นไป** ทั้ง `keep` และ `reframe`; เทสต์ต้องมีอย่างน้อย 20 แถว และ train อย่างน้อย 50 แถว โดยแบ่งเรื่องไม่ให้รั่วข้าม train/holdout
7. หลังตรวจข้อมูลและอนุมัติการเก็บใน repo สาธารณะ จึงจัดเก็บเป็น `training-lab/datasets/approved/shot-framing.jsonl` แล้วสั่ง **Actions → CPU Shot ML → Run workflow → approved**
8. โมเดลที่ได้จะเป็นเพียง `candidate-review` หรือ `rejected`, `active: false` เสมอ **ไม่เปิดใช้อัตโนมัติ** ต้องประเมินเรื่องที่ไม่เคยเห็นและให้คนอนุมัติ โปรโมตเป็น `approved, active: true` ด้วยกระบวนการอนุมัติแยก
9. เมื่อนำเข้าโมเดลอนุมัติใน Shot ML แล้ว กด **ให้ ML เสนอและยืนยันมุมกล้อง** โปรแกรมจะแสดงความเสี่ยงเดิม/ใหม่ก่อนถามยืนยัน แล้วจึงแก้กล้องอย่างเดียวผ่านตัวตรวจสอบโปรเจกต์

## ทำไมยังไม่ได้เทรน SVG จาก MP4 รอบ (7)

คลิปประตูน้ำรอบ (7) ยังไม่ใช่ตัวอย่างที่ผ่านเกณฑ์ โดยเฉพาะรูปร่างประตูน้ำ ความใหญ่ของตัวละครและการเคลื่อนไหวยกของ จะนำ MP4 ผิดมาจัดเป็น `keep` โดยไม่ถามผู้ใช้ไม่ได้ และโมเดลจัดมุมกล้องไม่ได้ฝึกภาพหรือการกระทำโดยตรง

ถ้าจะให้ AI สร้าง SVG, rig และท่าทางได้ด้วย ML จริง ต้องเพิ่มงานเฉพาะทาง, แหล่งข้อมูลที่มีสิทธิ์ใช้, คู่ตัวอย่าง SVG ก่อน/หลังแก้ที่ผ่านคนตรวจ และระบบประเมินผลงานภาพจริงแยกต่างหาก อย่าอ้างว่าผู้ช่วยทั้งหกเป็นโมเดลอิสระเพียงเพราะแสดงผลในหน้าจอ

**ขอบเขตความปลอดภัย:** ไฟล์โมเดล demo/rejected/candidate ถูกปฏิเสธในตัวแนะนำกล้อง; ไม่มีการส่งวิดีโอผู้ใช้ไป GitHub โดยอัตโนมัติ ไม่มีการดึง API โมเดลภายนอก และไม่เปลี่ยนกล้องโดยไม่กดยืนยัน
