## เปิดเว็บและ Deploy บน AWS Amplify

โค้ดเว็บหลักอยู่ที่ [index.html](./index.html) และมี [amplify.yml](./amplify.yml) สำหรับตั้งค่า Build สำเร็จรูป ไม่ต้องติดตั้ง npm หรือ Backend เพื่อเปิดหน้าแอป

1. เปิด [AWS Amplify Console](https://console.aws.amazon.com/amplify/home) แล้วเลือก **Create new app → GitHub**
2. เชื่อม GitHub (ถ้ายังไม่ได้เชื่อม) และเลือก Repository `tanawutmalirum29-ux/AI-ANIMATION`
3. เลือกสาขา `main`; Amplify จะอ่านไฟล์ `amplify.yml` จาก Repository
4. ตรวจว่าคำสั่ง Build คือการคัดลอก `index.html`, `animated-map.js`, `animated-map.css`, `cinematic-fx.js`, `cinematic-fx.css`, `character-interaction.js`, `character-interaction.css` ไปยัง `dist/` และ Artifact directory คือ `dist`
5. กด **Save and deploy** แล้วเปิดโดเมน HTTPS ของ Amplify เพื่อตรวจสอบการพากย์เสียงและไมโครโฟน

เมื่อเชื่อม Continuous Deployment แล้ว GitHub commit ใหม่ในสาขาที่ตั้งค่าไว้จะกระตุ้นให้ Amplify สร้างและเผยแพร่เวอร์ชันใหม่ (หาก Auto-build เปิดอยู่)

> สิทธิ์ไมโครโฟนต้องขอจากเบราว์เซอร์บนเว็บ HTTPS โดยตรง หน้าพรีวิวบางแบบอาจบล็อกได้ และการส่งออกวิดีโอบางรูปแบบอาจมีข้อจำกัดบน Safari/iPad

## แผนที่เคลื่อนไหว · Animated Map (v18)

เครื่องมือแผนที่ในหน้าสตูดิโอทำงานทั้งพรีวิวและการส่งออกวิดีโอ (ไม่ต้องเชื่อมบริการแผนที่ภายนอก):

1. เปิดโปรเจกต์ในเว็บ แล้วเลือกตอนและฉากที่ต้องการ
2. ในแถบเครื่องมือกด **แผนที่** และเลือกธีม **ทุ่งนา / กลางคืน / เมือง / แผนที่กระดาษ** เพื่อสร้างแผนที่
3. ตั้งรูปแบบ **เต็มเฟรม** หรือ **แผนที่มุมบนขวา** พร้อมชื่อแผนที่ จุดเริ่ม จุดหมาย เวลาเริ่ม/จบและเวลานับถอยหลัง
4. เพิ่ม/ลบจุดทางผ่าน ปรับพิกัด X/Y แบบเปอร์เซ็นต์ (0–100) และเลือกให้หมุดเคลื่อน **ตามเส้นทาง** หรือ **ตามตัวละครแรก**
5. เลื่อนแถบเวลาของฉากหรือกด **ดูครึ่งทาง** เพื่อตรวจเส้นทาง แล้วกด **ส่งออก** เพื่อบันทึกแผนที่เป็นส่วนหนึ่งของวิดีโอ

ข้อมูลแผนที่จะอยู่ใน `scene.animatedMap` ภายใน JSON โปรเจกต์ บันทึก/กู้คืนได้ตามระบบเดิม ไม่กระทบฉากเก่าที่ไม่มีแผนที่ ระบบ QA ตรวจการสร้าง แก้จุด บันทึก และ Canvas export ใน Chromium อัตโนมัติบน GitHub Actions

## Cinematic Effects Engine (v19)

เครื่องมือ **เอฟเฟกต์ภาพ** เพิ่มงานภาพยนตร์แบบตั้งเวลาต่อฉาก โดยต่อยอดจาก Lighting/Atmosphere เดิมที่มีอยู่:

- Preset **แสงจันทร์ / รุ่งเช้า / ไฟฉายกลางคืน / พายุฝน / ริมน้ำ / ปรับเอง**
- หมอก 3 ระดับความลึกและการลอยแบบ Parallax, ฝุ่นละออง, แสงจันทร์ แสงอาทิตย์ ลำแสงไฟฉาย คบเพลิง, ระลอกน้ำและแสงสะท้อน, โทนสี, เงาเคลื่อนไหว
- แยก Parallax ให้ชั้นภาพเวกเตอร์ `art`, `set` (หลังฉาก) และ `setf` (หน้าฉาก) ตามทิศการเคลื่อนกล้อง การใช้ภาพพื้นหลังแบนไฟล์เดียว **ไม่สามารถแยกวัตถุในภาพได้**
- มีเวลาเริ่ม/จบ Fade In/Out, คีย์เฟรมควบคุมความแรงเอฟเฟกต์ 7 ค่า และ Interpolation แบบ Smooth / Linear
- ใช้ Canvas2D painter เดียวกันใน Preview และ Export และบันทึกค่าลงใน `scene.cinematicFx` พร้อม Undo/Redo, JSON save/import
- เปิดเว็บ → เลือกฉาก → แถบเครื่องมือ **เอฟเฟกต์ภาพ** → เลือก Preset → ตั้งคีย์เฟรมที่ตำแหน่ง Playhead → Preview / Export

หมายเหตุ: Reflection เป็นแสงสะท้อนเชิงภาพ (procedural) โดยผู้ใช้ตั้งระดับผิวน้ำ ไม่ใช่ระบบ ray-tracing หรือการจำลองผิวน้ำจริง และประสิทธิภาพส่งออกขึ้นอยู่กับอุปกรณ์/เบราว์เซอร์

QA: `tests/cinematic-fx-smoke.cjs` ทดสอบ Chromium จริงร่วมกับ `tests/animated-map-smoke.cjs` ผ่าน GitHub Actions

## การสลับฉากและ Character Interaction (v20)

เพิ่มตัวเลือก **ฉาก** ใต้แถบเวลา Preview พร้อมปุ่ม ◀ ▶ สำหรับเปลี่ยนฉากโดยตรงบน iPad/มือถือ และหน้าเครื่องมือ **ตัวละคร / เปลี่ยนฉาก** ใน Workspace

- **สร้างฉากใหม่ต่อเนื่อง:** เลือกสถานที่ใหม่หรือฉากเวกเตอร์ แล้วกด **สร้างฉากถัดไปแบบต่อเนื่อง** คัดลอกตัวละครที่มีอยู่โดยใช้ตำแหน่ง/ท่าท้ายฉากก่อนหน้า และคงพร็อพที่ตัวละครกำลังถือ
- **เปลี่ยนสถานที่ฉากปัจจุบัน:** เปลี่ยนสถานที่หรือฉากเวกเตอร์แล้วให้โปรแกรมล้างภาพพื้นหลังที่ขัดกัน เพื่อแก้ปัญหาเลือกฉากใหม่แต่ยังเห็นฉากเดิม
- **แก้การเลือกฉากค้าง:** การเพิ่ม/คัดลอก/ลบ/เลื่อนฉากผ่านปุ่มใน Inspector จะปรับ Playhead ให้ตรงกับฉากที่เลือกโดยไม่อ้างตำแหน่งเวลาเก่า
- **Interaction Timeline:** เพิ่มคำสั่ง **หยิบและถือ**, **วาง**, **เปิด/ปิดประตู** โดยเลือกระหว่างตัวละคร/พร็อพ/เวลาภายในฉาก/มือซ้ายหรือขวา และแก้/ลบคำสั่งเดิมได้
- **Rig Hand Grip:** สิ่งของถูกยึดกับข้อมือจริงของ Rig และติดไปใน SVG ทั้ง Preview และวิดีโอ Export; สามารถนำสิ่งที่ถืออยู่ติดไปฉากถัดไป
- การลบพร็อพจะลบ/เลื่อนดัชนี Interaction ให้ตรงกับพร็อพที่เหลือเสมอ
- ฉากเก่าไม่มี Interaction จะยังเล่นและแสดงผลตามเดิม ข้อมูลจะเก็บใน `scene.interactions` และ `scene.interactionInitialHold` พร้อม Undo/Redo และ JSON Save/Import

**ข้อจำกัด:** ตอนนี้การจับของเป็นการติดไอเทมเข้ากับจุดข้อมือที่กำหนด ไม่ใช่ IK แบบแก้ท่ามืออัตโนมัติ; การเปิดประตูใช้แอนิเมชัน 2D; การปีนบันไดและ AI วิเคราะห์ประโยคยังไม่รวมในรุ่นนี้

## ปรับปรุงตัวละคร การวาด การหัน ท่าทาง (v21)

- **ลำตัว/คอ/เท้า:** ลำตัวในมุมข้างและเฉียงหนาขึ้น (เดิมบางเป็นแผ่น กว้างราว 3 หน่วย), เพิ่มคอที่เชื่อมหัวกับไหล่ (เดิมไม่ได้วาด), เท้าเป็นรองเท้าจริงหมุนตามข้อเท้า, ขาไกลแยกออกจากขาใกล้ในท่ายืนมองข้าง และจมูกด้านข้างไม่แหลมเกินจริง
- **แขน/ขาใกล้-ไกล:** มุม ≥90° เดิมสลับเฉพาะแขน ไม่สลับขา และท่าชี้/โบกมือด้านข้างไปอยู่หลังลำตัวสีเข้ม ตอนนี้แขนและขาสลับพร้อมกันเมื่อหันหลังเกิน 105° ท่าด้านข้างใช้ข้าง R เป็นข้างใกล้กล้องตามที่ rig กำหนด
- **มุมหน้า/หลัง:** ท่านั่ง พิมพ์ ยกของ อ่าน โทรศัพท์ คิด ปรบมือ ย่อ คุกเข่า ไม่กางแขนขาออกด้านข้างอีก (ย่นสัดส่วนเชิงลึก) ท่าเดิน/วิ่ง/ย่องมุมหน้าไม่กางขา
- **การหัน:** เมื่อเส้นทาง (`route`) เปลี่ยนทิศจากจุดก่อนหน้า ตัวละครจะหมุนผ่านมุมหน้าก่อนเดิน (สูงสุด 0.45 วินาที) แทนการพลิกซ้าย-ขวาทันที ไม่ทำงานถ้าตั้ง `bodyYaw`/`toBodyYaw`/`view` เอง

## ต่อเนื่องข้ามฉาก: สภาพอากาศ แสง และ Transition (v22 + v23 Phase 1)

> หมายเหตุ: ไฟล์ zip ที่รับช่วงมามีถึง v21 เท่านั้น งาน v22 ที่ระบุไว้ในพรอมต์ไม่อยู่ในไฟล์ จึงทำใหม่ในรอบนี้พร้อมส่วนของ v23 Phase 1

- **สภาพอากาศชุดเดียว พรีวิว = ส่งออก:** `filmAtmosphere()` วาดบน Canvas แบบ deterministic ผูกกับเวลาต่อเนื่อง `atmoClock()` (= `T`) รองรับ rain, storm, snow, fog, wind, dust, fireflies, stars (เดิมส่งออกไม่วาด fog/wind/dust เลย และพรีวิวใช้ CSS ตามเวลาจริง ลากสไลเดอร์แล้วฝนไม่ตาม) CSS เดิมยังเป็น fallback เมื่อเปิด `prefers-reduced-motion`
- **เฟดสภาพอากาศข้ามฉาก:** ถ้าฉากติดกันใช้สภาพอากาศต่างกัน จะ cross-fade ตามความยาว transition (รอยตัด `cut` ใช้ 0.25 วินาที `FILM_FADE`) ถ้าเหมือนกันจะเดินต่อเนื่องไม่รีเซ็ต
- **แสงเฟดข้ามฉาก:** `glow`, `vignette`, จุดโฟกัส และสีแสงฉาก (`scene.light`) ค่อยๆ เปลี่ยนตามความยาว transition (ยกเว้น `cut`) ทั้งพรีวิวและส่งออก
- **Cinematic FX:** หมอก/ฝุ่น/ระลอกน้ำใช้นาฬิกาต่อเนื่อง; ฉากติดกันที่ใช้ preset เดียวกันไม่เฟดออก-เข้าซ้อนกัน; เอฟเฟกต์ฉากเดิมเฟดออกระหว่าง transition
- **แก้บั๊ก parity:** (1) ภาพฉากเดิมในพรีวิวใช้ id ของ SVG ซ้ำกับฉากใหม่ ทำให้ท้องฟ้าฉากเดิมเปลี่ยนสีกลางรอยต่อ (2) ตอนส่งออก `slide/push` เลื่อนซ้อนสองรอบ และ `zoom` ซ้อนสองรอบ (3) `fade` ส่งออกไม่ตรงพรีวิว (4) รัศมี `iris` ต่างกัน (5) `scene.light` ไม่ถูกส่งออก
- **ลดอาการกระตุก:** เลิกหยุดเสียงทุกครั้งที่เตรียมภาพฉากเดิม, prefetch ภาพฉากเดิมล่วงหน้า 0.7 วินาที, เปลี่ยนฉากระหว่างเล่นจะแค่ไฮไลต์ไทม์ไลน์ แล้วค่อยสร้าง Inspector/Timeline ใหม่ตอนหยุดเล่น, ล้างแคชภาพฉากเดิมเมื่อแก้ไข
- ฟิลด์ใหม่: `episode.continuity.atmosphereClock` (วินาที, ไม่บังคับ) เริ่มต้น 0 ไม่ใส่ก็ได้

**พฤติกรรมที่เปลี่ยนในวิดีโอส่งออกของโปรเจกต์เก่า:** สีแสงฉาก (`scene.light` / แสงประจำสถานที่) ซึ่งพรีวิวแสดงมาตลอดแต่ส่งออกไม่เคยใส่ ตอนนี้ถูกใส่ให้ตรงกับพรีวิว

**ยังไม่ได้ทำ (v23 Phase 2–3):** ฉากเดิมยังมีชีวิตระหว่าง transition (A1), โหมด preroll/handle (A2), ต่อเนื่องข้ามตอนและปุ่มสร้างตอนถัดไป (B2 ส่วน UI), เสียงบรรยากาศต่อเนื่อง/L-cut/J-cut (B4), การหันและท่าข้ามฉาก (C1–C2), easing/กล้อง match cut (A6, C3), UI ตั้งค่า (D2), กฎ QA ใหม่ (D3), ท่านอน/สัตว์ (C4)

QA: `tests/scene-transition-smoke.cjs` (ตั้ง `BASELINE=<โฟลเดอร์ v21>` เพื่อเทียบความเข้ากันได้ย้อนหลัง, `PERF_ONLY=1 ROOT=<โฟลเดอร์>` เพื่อวัดความกระตุกอย่างเดียว)

## พากย์อัตโนมัติฟรี (v38 · Lambda + Edge TTS)

ปุ่ม **✦ พากย์อัตโนมัติ** อยู่ในห้องพากย์ (แท็บ “พากย์ทันที”) สร้างเสียงไทยจากซับของแต่ละช่วง แล้ววางเป็นคลิปเสียงพากย์ที่เวลาเริ่มของช่วงนั้น เข้า Sound Desk, J/L-cut และ Export ได้เหมือนคลิปที่อัดเอง เลือกขอบเขตได้: **ฉากนี้ / ทั้งตอน / ทั้งเรื่อง** และกด undo ครั้งเดียวเพื่อลบเสียงที่เพิ่งสร้างทั้งหมด

- เสียง: โปรไฟล์เสียงทุ้ม/ลึก/ผู้สูงอายุ/ตัวร้าย → `th-TH-NiwatNeural` (ชาย) นอกนั้น → `th-TH-PremwadeeNeural` (หญิง) แล้วโปรไฟล์เสียงเดิมแต่งเสียงต่อ (pitch/EQ/echo)
- ถ้าเสียงยาวกว่าช่วงซับ แอปจะรายงานว่าฉากไหนเกินกี่วินาที

### ติดตั้งฝั่งเซิร์ฟเวอร์ (ทำจากมือถือได้ ไม่ต้องมีคอม)

1. อัปโหลดโฟลเดอร์ `autodub/` ขึ้น GitHub พร้อม `index.html` ใหม่ (Amplify ไม่เอา `autodub/` ขึ้นเว็บ เพราะ `amplify.yml` คัดลอกเฉพาะไฟล์ที่ระบุ)
2. เปิด AWS Console แล้วเปิด **CloudShell** (ไอคอน `>_` บนแถบบน)

   ```

   ```

**เปลี่ยนรหัสผ่านอย่างปลอดภัย:** ใน CloudShell ใช้ `read -rs SITE_PASSWORD; export SITE_PASSWORD; bash deploy.sh https://main.d1wc6w01kiwpnk.amplifyapp.com; unset SITE_PASSWORD` ห้ามพิมพ์รหัสผ่านตรง ๆ ในประวัติคำสั่ง

**ขอบเขตการป้องกัน:** รหัสผ่านตรวจที่ Lambda จริงเพื่อควบคุมการใช้งาน AI แต่สตูดิโอนี้เป็น Static Hosting: ซอร์ส HTML/JavaScript ที่ Amplify แจกยังดาวน์โหลดได้แม้มีหน้ากรอกรหัสผ่าน หากต้องการห้ามเข้าถึงเว็บไซต์และไฟล์จริง ๆ ต้องเปิด Amplify Access Control/Basic Auth เพิ่ม (ซึ่งอาจต้องล็อกอินอีกครั้ง) อย่าเก็บข้อมูลลับในซอร์สเว็บ

เซสชันบันทึกใน localStorage ของเบราว์เซอร์ 8 ชั่วโมง ผู้ที่ใช้เครื่องเดียวกันอาจเข้าใช้งานได้จนกว่าจะออกจากระบบ จึงควรกด Logout บนเครื่องสาธารณะ ถ้าเผยแพร่ให้คนอื่นใช้จำนวนมากควรเพิ่ม AWS WAF rate limiting หรือระบบบัญชีผู้ใช้ — ตัวจำกัดความถี่ใน Lambda เป็นเพียง best-effort

ตัวแปร `STORY_STUDIO_API_URL` เป็น URL สาธารณะ ห้ามใส่ `SITE_PASSWORD_HASH` หรือ `SESSION_SECRET` ลงในตัวแปรที่เผยแพร่ไปหน้าเว็บ

## AI Production Workspace — Local AI ฟรี, ประวัติ, สมุดเรื่องและคลังโปรเจกต์

เปิดเว็บ Story Studio → **AI คุยงาน** บนแถบพรีวิว หรือ **AI สั่งงาน** ใน Workspace หรือเมนูโปรเจกต์ → AI Workspace.

### สิ่งที่ทำได้

- **AI 7 บทบาท แต่ใช้โมเดลจริงตัวเดียวเรียกทีละงาน:** ผู้กำกับ, เขียนบท, วางเฟรมและซับ, แอนิเมชัน, เสียงประกอบ, ผู้กำกับพากย์ (Edge TTS เดิมสร้างเสียงจริง), และ QA; ไม่ต้องโหลด 7 โมเดล
- **แชตสั่งงาน + คิวงาน + ผลงาน:** เลือกบทบาท ส่งคำสั่ง ดูสถานะรอทำ/กำลังทำ/เสร็จ/ผิดพลาด พร้อมประวัติแชตไม่เกิน 180 รายการ และประวัติงานล่าสุดไม่เกิน 130 รายการ; งานที่สะดุดเพราะปิดเว็บจะระบุว่า interrupted ให้เริ่มใหม่ได้
- **Story Bible และสรุปแต่ละตอน:** แกนเรื่อง โลก/กฎ ตัวละคร เหตุการณ์และปมค้าง พร้อมสรุปตอนปัจจุบัน AI อ่านเป็นบริบทในการตอบคำถามถัดไป จึงช่วยรักษาความต่อเนื่องเมื่อทำเรื่องยาว ไม่ใช่ความจำที่โมเดลจำเอง
- **เสนอ Patch ปลอดภัยก่อน:** ถ้าโมเดลส่ง JSON `ops` ระบบแสดงคำสั่งให้ตรวจ ผู้ใช้ต้องกดยืนยันและผ่าน `StudioAPI.apply({dryRun:true})` ก่อนแก้ฉากจริง รองรับ Undo; โมเดลไม่ได้แก้หรือสร้างคลิปอัตโนมัติทันที
- **บันทึกเวอร์ชันโปรเจกต์:** IndexedDB เก็บ snapshot ตามชื่อ/เวลา/จำนวนฉาก เพื่อเปิดกลับมาได้; ดาวน์โหลด JSON สำรองพร้อมประวัติและสมุดเรื่อง; เปิด JSON ด้วยระบบเดิม

### การโหลด AI ฟรีในเบราว์เซอร์

เลือก **Qwen2.5 0.5B** (รองรับภาษาไทยพื้นฐาน แต่ไม่ควรคาดหวังคุณภาพเท่าระบบคลาวด์) แล้วกด **โหลด AI ในเครื่อง**. ใช้ `@mlc-ai/web-llm` เวอร์ชันตรึง `0.2.86` โหลด JavaScript จาก CDN และโมเดล MLC จากโฮสต์โมเดลบนอินเทอร์เน็ตครั้งแรก; cache ตามเบราว์เซอร์; ไม่ส่ง prompt ไปยังเซิร์ฟเวอร์ LLM; หลังโหลดจึงประมวลผลผ่าน WebGPU บนอุปกรณ์.

**ข้อจำกัดสำคัญ:** การโหลดโมเดลต้องมี HTTPS, WebGPU และ RAM/GPU ที่พอ (ประมาณ 1 GB GPU สำหรับ 0.5B แต่ขณะใช้งานจริงอาจใช้หน่วยความจำมากกว่านั้น); Safari/iPad บางรุ่นไม่มี WebGPU หรือระบบยุติแท็บเมื่อหน่วยความจำไม่พอ. ไม่สัญญาว่าทำงานออฟไลน์ได้เสมอเพราะ runtime/CDN และไฟล์โมเดลต้องเข้าถึงครั้งแรก หาก GPU ไม่รองรับ ยังใช้คิวงาน บันทึกแชต สมุดความต่อเนื่อง และเซฟโปรเจกต์/JSON ได้ แต่ไม่ได้สร้างคำตอบ AI จริง. ไม่มี API Key เสียเงินและไม่รันโมเดลบน AWS Lambda.

**ความปลอดภัยข้อมูล:** บันทึกแชต/สมุดเรื่องภายใน `project.aiWorkspace` และในไฟล์ JSON โปรเจกต์. สำรอง JSON เป็นประจำ โดยเฉพาะเมื่อมีไฟล์เสียง base64 ขนาดใหญ่; IndexedDB อาจถูกเคลียร์หรือลบโดยระบบ และไม่ซิงก์ข้ามเครื่อง. โหมดรหัสผ่านเว็บไซต์ก่อนเข้าสตูดิโอแยกจาก Local AI; อย่าใส่ข้อมูลลับใน public GitHub และอย่าเข้าใจว่าหน้ากั้นรหัสผ่านทำให้ไฟล์ static เป็นส่วนตัว.

QA: `node tests/local-ai-core-smoke.cjs` และ `node tests/local-ai-workspace-smoke.cjs` (Playwright Chromium; ตัวทดสอบไม่ได้ดาวน์โหลดโมเดลจริง). การสร้างคำตอบของโมเดลและคุณภาพภาษาไทยต้องตรวจบนอุปกรณ์จริงหลัง Deploy.

## Art Vault — ให้ AI เสนอวาดของและส่งเข้า GitHub อย่างปลอดภัย

เปิด Story Studio → AI คุยงาน → **คลังรูป / GitHub** เพื่อใช้ของสำเร็จรูปในฉาก หรือเปิดแท็บ **ออกแบบ / ส่ง PR** เพื่อสร้างรูปใหม่ด้วย JSON รูปทรงที่ตรวจสอบแล้ว

- เริ่มต้นมีโคมไฟตั้งพื้น ต้นไม้ใบกลม หมอกปริศนา และโต๊ะทำงานไม้ ใช้ได้ทันทีในพรีวิวและการส่งออก ภาพที่ใส่ในฉากจะติดไปกับโปรเจกต์ JSON และกด Undo ได้
- AI-7 นักวาดสินทรัพย์ ใช้ WebLLM ในเครื่องเพื่อเสนอไฟล์ `assetSuggestion` แบบรูปทรง (circle, ellipse, rect, polygon, line) → เปิดตรวจภาพ → ใส่ในฉาก หรือกดส่ง GitHub เป็น Pull Request
- ระบบ **ไม่รับ SVG, JavaScript หรือ HTML แบบอิสระ** จากโมเดล และไม่มีสิทธิ์แก้ไฟล์โค้ดทั่วไปได้; เซิร์ฟเวอร์เขียนเฉพาะ `assets/library.json` ใน branch ใหม่ แล้วเปิด PR เพื่อให้ตรวจและ Merge ก่อนเผยแพร่
- เมื่อ PR ถูกรวมเข้า `main` และ Amplify Deploy ผ่าน รายการใหม่จะปรากฏในคลังของสำเร็จรูปบนเว็บไซต์ทุกเครื่อง

### ต่อ GitHub กับ Lambda เพียงครั้งเดียว

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens: สร้าง token จำกัด **เฉพาะ repository `tanawutmalirum29-ux/AI-ANIMATION`**, ให้สิทธิ์ **Contents: Read and write** และ **Pull requests: Read and write** เท่านั้น (Metadata Read เป็นสิทธิ์ปกติ) เลือกวันหมดอายุตามที่ต้องการ ไม่ต้องเพิ่ม Actions/Administration หรือสิทธิ์ครอบคลุมทุก repository

หลังตั้งรหัสผ่านเว็บไซต์และรัน `autodub/deploy.sh` ฉบับล่าสุดแล้ว เปิด **AWS CloudShell** บัญชีและ region เดิม แล้วรัน:

```bash
cd ~/AI-ANIMATION
git pull --ff-only
cd autodub
bash deploy.sh https://main.d1wc6w01kiwpnk.amplifyapp.com
bash enable-github.sh
```

`enable-github.sh` จะถาม token โดยซ่อนข้อความที่พิมพ์ และเก็บในตัวแปร Lambda ชื่อ `GITHUB_ASSET_TOKEN` เท่านั้น ไม่มีการฝังใน HTML/JavaScript, JSON โปรเจกต์, localStorage หรือ GitHub โค้ด; ห้ามส่ง token ในแชต

หากเคยอัปเดต Lambda ก่อนเพิ่มไฟล์ `github_assets.py` ต้องรัน `deploy.sh` ใหม่ก่อนเสมอ Token ที่เพิ่มแล้วจะถูกเก็บไว้ขณะรัน deploy ครั้งต่อไป

**ขอบเขต:** โมดูลนี้วาดเวกเตอร์ 2D จาก primitive แบบจำกัด ไม่ใช่ระบบสร้างภาพ AI เต็มรูปแบบ, ใช้เซิร์ฟเวอร์ GitHub REST เพียงเพื่อเสนอ PR หลังผู้ใช้กดยืนยัน การเปลี่ยนซอร์สโค้ดหรือขยายไลบรารีสำหรับทรัพยากรประเภทอื่นต้องมีการพัฒนาระบบแยก พร้อมขอบเขตสิทธิ์/การทดสอบอย่างเหมาะสม

**ความปลอดภัย:** GitHub PAT ใน Lambda เป็นข้อมูลลับ ควรจำกัด repo/สิทธิ์/อายุ token และเปลี่ยนเมื่อหมดอายุ หากใช้งานหลายคนควรมีระบบสิทธิ์รายบัญชีและป้องกันการเรียก API หลายครั้ง ตัวจำกัดการส่ง PR ใน Lambda แบบ in-memory เป็นเพียง best effort
